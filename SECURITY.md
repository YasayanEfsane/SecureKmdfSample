# Security Policy

## Supported Versions

Security fixes are applied to the latest release and the `main` branch. Older
sample revisions may not receive backports.

## Reporting a Vulnerability

Please use GitHub's **Security** tab and submit a private vulnerability report
when that option is available. If private reporting is unavailable, open a
minimal issue asking the maintainer for a private contact channel. Do not place
exploit code, crash dumps containing sensitive data, or unpatched vulnerability
details in a public issue.

Include the affected commit or release, Windows and WDK versions, reproduction
conditions, expected impact, and the smallest safe proof of concept. Allow the
maintainer reasonable time to investigate and publish a fix before disclosure.

## Research Scope

Test only systems you own or are authorized to assess. Prefer an isolated VM
with snapshots. Do not use this sample to bypass security controls, disrupt
third-party systems, or access data without permission.

This educational sample reduces common IOCTL risks but does not claim to be
vulnerability-free or production-certified.
